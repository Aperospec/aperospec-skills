# Aperospec SD Patterns

## Slide Outline Template

```markdown
## Slide X: [Concept-forward title]

Narrative role:
[Opening / why-now / root cause / worldview / emotion shift / identity / exhibit / technology / reconstruction]

Page paragraph:
[One concise paragraph explaining what this page expresses and what the audience should feel or understand.]

Core idea sentence:
[The one sentence the image must visually translate.]

Full-bleed image direction:
[Specific cinematic background: location, time, light, people or traces, material, camera, emotional temperature, symbolic detail.]

Image match rationale:
[Why this image is the right visual expression of the core idea, not just a related picture.]

Exhibit or interaction:
[Optional: what the audience sees, does, chooses, learns, or becomes.]
```

## Full Deck Template

```markdown
Deck thesis:
[The central worldview sentence.]

Core image:
[One image direction that can represent the whole project.]

Emotional curve:
[Enter -> Attract -> Deepen -> Unease -> Pressure -> Collapse -> Reflection -> Reconstruction]

Slide structure:
1. [Title world]
2. [Why now]
3. [Root cause]
4. [Worldview engine]
5. [Emotional curve]
6. [Spatial or experience structure]
7. [Identity immersion]
8. [Key exhibit 1]
9. [Key exhibit 2]
10. [Technology or interaction logic]
11. [Future consequence or reconstruction]
12. [Closing belief]
```

## Proposal Deck Spine

Use this spine when the user asks for a complete proposal deck.

```markdown
1. World cover:
   [Full-bleed image + oversized title + one thesis sentence]

2. Era legitimacy:
   [Policy, market, history, social trend, institutional background, or cultural context]

3. Human or cultural insight:
   [What people now desire, fear, lack, or misunderstand]

4. Core contradiction:
   [Why the old solution cannot answer the new condition]

5. Concept bridge:
   [The sentence that connects two worlds: online/offline, culture/technology, history/future, individual/social]

6. System proposal:
   [Platform, space, IP system, exhibition route, product feature system, or operating model]

7. Key mechanisms:
   [How the system works: scene/content/activity IP, flywheel, tasks, NFR, AI NPC, rights center, community, etc.]

8. Proof and execution:
   [Case studies, architecture, process, capability matrix, roadmap, team, revenue, or value proof]

9. Future vision:
   [Reconstruction image: what this system becomes for people, culture, city, industry, or civilization]
```

## Common Page Types

### World Cover

```markdown
Title:
[One large phrase that names the world]

Subtitle:
[One sentence explaining the thesis]

Image direction:
[A full-bleed cultural, urban, product, travel, or historical image that lets the audience feel the world before reading]

Image match:
[Explain how the visual contains the deck thesis]
```

### Era Legitimacy Page

```markdown
Title:
[Policy / market / history / cooperation / social trend title]

Lead:
[Why this topic is necessary now]

Evidence blocks:
- [Official background or policy]
- [Market or audience change]
- [Technology or cultural condition]

Design note:
[Use white/document-like layout for official credibility, or black analytical layout for market/industry proof.]

Image rule:
[Use documents, official interfaces, institutional spaces, charts, or archival materials only when they directly prove the page's claim.]
```

### Core Pain Point Page

```markdown
Title:
核心痛点

Lead:
[The emotional or behavioral gap in one sentence]

Pain points:
1. [Pain point name] - [What is missing]
2. [Pain point name] - [Why current behavior is shallow]
3. [Pain point name] - [Why value cannot continue]

Design note:
[Use sparse layout, large type, and strong contrast. Pain points should feel like diagnosis, not a feature list.]

Image rule:
[Show the missing emotional condition or broken behavior, not a generic unhappy user.]
```

### Value Flywheel Page

```markdown
Title:
价值飞轮

Cycle:
1. [Initial content or asset enters]
2. [User displays, shares, or participates]
3. [Social or offline conversion happens]
4. [More brands, culture, or rights join]
5. [More users and creation return]

Center:
[AI center, IP center, community, city resource, or operating engine]
```

### IP Mapping Page

```markdown
Title:
[Project name] 承载多模态核心 IP

IP types:
- Scene IP: [landmarks, spaces, visual symbols, geography]
- Content IP: [stories, figures, rituals, history, knowledge]
- Activity IP: [festivals, missions, events, games, offline actions]

Bridge:
[How these IP types move between digital community and real-world experience]
```

### Online-Offline Bridge Page

```markdown
Title:
[虚实的链接 / 连接线上线下的新纽带 / 从线上社交到线下体验]

Loop:
[online action] -> [identity or asset] -> [offline right or experience] -> [memory/content] -> [return to online social sharing]

Proof:
[QR entry, app screen, task, NFR, membership, ticket, route, check-in, reward, or redemption]

Image rule:
[The image should visibly contain both sides of the bridge, or a transition object that connects them.]
```

### Function-As-Key Page

```markdown
Title:
[Five core functions / solution keys]

Lead:
[These functions are not features; they are keys that unlock the pain points.]

Keys:
1. [Function] -> [Pain point solved] -> [User scene]
2. [Function] -> [Pain point solved] -> [User scene]
3. [Function] -> [Pain point solved] -> [User scene]
```

### Architecture Or Capability Page

```markdown
Title:
[System architecture / support system / capability base]

Layers:
- Presentation layer: [front-end, applet, Web3D, screen, device, space]
- Interaction layer: [tasks, controls, AI, NPC, community, gamification]
- Data layer: [collection, analysis, user behavior, asset, security]
- Operation layer: [content, traffic, campaigns, CRM, conversion]

Design note:
[Dense is acceptable if hierarchy is clear. Use grouped blocks, columns, and strong labels.]
```

### Future Vision Page

```markdown
Title:
未来展望

Lead:
[What this system becomes after growth]

Future blocks:
- [Culture or civilization value]
- [Economic or industry value]
- [User or community value]
- [Technology or platform value]

Image direction:
[A restrained future image connected to the original world, not generic sci-fi.]

Image match:
[Explain how the future image resolves the deck's original contradiction.]
```

## Critique Checklist

- Does the deck start from why-now and root cause, rather than a generic project introduction?
- Is there one core image that can carry the whole worldview?
- Does the deck alternate between emotional image pages and dense proof pages?
- Does each page have a narrative role?
- Does each title express a point of view?
- Is the paragraph short enough for a slide page?
- Does the image match the concept, not merely the topic category?
- Can the image be read as the visual translation of the page's core sentence?
- Would replacing the image with another generic image weaken the page's meaning? If not, the image is not specific enough.
- Are policy, market, history, or institutional proof pages placed before the solution asks for belief?
- Is the bridge clear: virtual/real, online/offline, culture/technology, history/future, individual/social?
- Are functions framed as solutions to pain points, not isolated product modules?
- Are exhibits derived from emotional and narrative beats?
- Does technology serve the world instead of showing itself off?
- Does the deck end with reconstruction, not just summary?
