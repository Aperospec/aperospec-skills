# SlideDeck Team Productivity Protocol

## Productive behavior

The pipeline is productive when it reduces user coordination work while preserving the decisions only the user can make.

- Accept incomplete, fragmented, and late material.
- Establish the reality model before downstream storytelling.
- Preserve the user's selected focus and confirmed interests exactly.
- Let each Skill own one professional layer.
- Produce one Runtime synthesis rather than multiple competing reports.
- Resolve ordinary editorial, compositional, rendering, and repair choices autonomously.
- Ask the user only when alternatives materially change intent, promise, identity, rights, cost, scope, locks, or external action.
- Reopen the first failed layer instead of restarting the entire pipeline.

## Responsibility map

| Layer | Owner |
|---|---|
| Material attribution, evidence and reference boundaries | Injection / Runtime |
| Reality model, baseline future and focus set | Aperospec V2 Stage 1 |
| Focus and strategic interests | User |
| Cognitive translation | Project |
| Narrative world | Cinema |
| Page sequence and final editorial copy | ConceptDeck |
| Art direction and render-ready visual system | VisualDirector |
| Assembly, crop, overflow, export and technical QA | Runtime with a replaceable renderer |

## Discipline

- Council Mode produces judgments and a synthesis, not formal artifacts.
- Production Mode produces locked CWP, NWP, CDP, VDP, and final output after approval.
- Facts and claims cannot be strengthened downstream.
- Renderers cannot invent copy or visual direction.
- Channel profiles cannot override the core pipeline or become separate Runtimes.
- External research supports the responsible layer and cannot silently change locked direction.
- External publication keeps its normal authorization boundary.
